# WASM backend interop

Interop status for the browser/WASM WebTransport backend (`crates/wasm` +
`@webtransport-bun/webtransport/wasm`). The wasm stack is still the sans-IO QUIC
+ HTTP/3 + WebTransport implementation driven over a `UdpTransport`
(in-memory relay, Bun UDP, or Chromium Direct Sockets).

This file documents the current proof paths. It does not declare release
readiness on its own; release readiness still depends on
`docs/release-status.json`.

## Browser policy and IWA proof

The browser-hosted server path now documents both Chromium policy tracks:

- legacy Chromium through 150 keeps `direct-sockets-private`
- Chrome 151+ uses `local-network` and `loopback-network`

The current IWA manifest grants both paths so the same bundle can be exercised
across the supported browser range. The automation flow also pregrants local
network access so the proof can run without a human permission prompt.

The scheduled `iwa.yml` workflow packages one signed bundle and then runs the
same proof against pinned Playwright Chromium and the current Chrome Beta
channel. The upload artifacts are commit-bound:

- `.release-evidence/iwa/evidence.json`
- `.release-evidence/iwa/evidence-chrome-beta.json`
- `.release-evidence/iwa/origin.txt`
- `.release-evidence/iwa/webtransport-wasm-iwa.wbn`
- `.release-evidence/iwa/webtransport-wasm-iwa.swbn`

The proof JSON records the candidate `sourceCommit` and both bundle digests:
`unsignedBundleSha256` and `signedBundleSha256`.

## Manual development harness

1. Build the web-target wasm bundle and the browser-facing package bundle.
2. Install the IWA bundle in Chromium with the isolated-web-app developer-mode
   path from `examples/webtransport-wasm-iwa/README.md`.
3. Start the embedded server and copy the printed `serverCertificateHashes`
   value.
4. From a normal Chrome tab or another IWA, connect with the native API:

   ```js
   const wt = new WebTransport("https://127.0.0.1:4433/", {
     serverCertificateHashes: [
       {
         algorithm: "sha-256",
         value: Uint8Array.from(atob(HASH), (c) => c.charCodeAt(0)),
       },
     ],
   });
   await wt.ready;
   const writer = wt.datagrams.writable.getWriter();
   await writer.write(new TextEncoder().encode("hello"));
   ```

   The wasm server echoes the datagram back. The certificate must still be
   ECDSA P-256 with a total validity window of 14 days or less.

## Current server proof

- The browser `WebTransport` client completes datagram, bidi, and uni exchanges
  against the wasm server in the Playwright harness.
- The IWA proof exercises datagrams, uni/bidi streams, RESET_STREAM,
  STOP_SENDING, peer close, eight reconnects, and certificate rotation.
- The release claim is still pending until the evidence is bound to the final
  candidate SHA in `docs/release-status.json`.
