## Freeze decisions — DECIDED NOW, not "during the phase"

Rev 1 deferred three permanent public shapes to implementation time. A decision made under phase
pressure gets frozen forever. Decided:

- **A4 — `BufferSource` only. Delete `valueBase64`.** This is an rc; dual-accept means two frozen shapes
  forever, which is the exact defect A4 exists to remove.
- **A5 — `onSession` failure closes the session. No opt-out option.** An option would be a second frozen
  surface added to work around a bug.
- **C2 — native `getStats()` keeps `0`; the JSDoc is corrected instead.** Widening `number` →
  `number | undefined` breaks every consumer doing arithmetic and diverges from the W3C dictionary
  (`unsigned long long`). The audit rated MEDIUM-8 explicitly non-blocking and forward-compatible.
- **A1/A8 — per-class codes.** `normalizeToBrowserName` (`index.ts:115-177`) routes **two** DOMException
  names off seven `message.includes` blocks: `"cannot be used with allowPooling=true"` and
  `"only supports algorithm"` → `NotSupportedError`, the rest → `TypeError`. One code cannot express
  that. Ship **`E_INVALID_ARGUMENT` + `E_UNSUPPORTED_ARGUMENT`**, and **delete the message wall in A1**
  rather than leaving C4 to inherit it.
- **A2 — `E_SESSION_CLOSED` is retained** with narrowed meaning (use-after-close), with
  `E_SESSION_CLOSED_LOCAL`/`_REMOTE` added alongside. 67 live references across `src/`, 6 test files and
  `docs/SPEC.md` depend on it.
- **Union widening is a typed break.** `ErrorCode` (`errors.ts:31-42`) is a closed union: every added
  member breaks consumers with an exhaustive `switch` + `never`. Every new code must be added to
  `codeToSource` **and** `normalizeToBrowserName` (whose switch has **no `default`**, so an unlisted code
  silently yields `undefined` under `strictW3CErrors`). Flag the widening in the CHANGELOG.

### A2a/A2b/A2c — the error contract (rewritten)
Rev 1's premise was false (see Corrections §1). Revised:
- **A2a** — `WtError { code: WtCode, detail: String }` in `crates/native/src/error.rs`;
  `impl From<WtError> for napi::Error<String>` so the **48 sync** entrypoints set a real `err.code`.
  `toWebTransportError` (`index.ts:195-203`) reads `err.code` first.
  **Before committing the design, compile one sync fn returning `Error<String>`** — the `#[napi]`

  and nobody has verified it.
- **A2b** — classify upstream errors. Measured `napi::Error::from_reason` sites: `server.rs` 41 (13

  rev 1's "an absent match is a hard error" would convert every unclassified upstream error into a

  to terminate iterators cleanly.
- **A2c** — the **28 async** entrypoints: resolve a tagged `{ok:false, code, detail}` the thin TS wrapper
  throws (preferred), or an anchored `/^(E_[A-Z_]+): /` parse confined to an **enumerated list with a
  test asserting the list does not grow**. Record that napi-rs **v3** lifts the async restriction, and
  that adopting it is explicitly out of scope for this release — so the fallback is visibly temporary.

### B5 — bench gate (hardened)
Rev 1's ancestry assertion is satisfiable by a baseline that was never measured. Required additions:
- baseline record carries the bench artifact's **SHA-256**, and the gate verifies that artifact's own
  `commit` field equals `baseline.commit` (ancestry alone admits a commit where the bench never ran, or
  one chosen after the fact for favorable numbers);
- **max ancestry distance** (previous tag, or ≤N commits) on the release branch's first-parent chain —
  plain ancestry permits per-commit re-baselining where a 2%/commit drift never trips;
- validity keyed on machine identity **and toolchain hash**;
- an explicit **approver field**, so re-baselining is a reviewable act rather than a file edit — note the
  maintainer both captures and approves under the local-binding decision, so this is the only check on
  self-approval;
- ancestry is **uncheckable under `actions/checkout`'s default shallow clone** — set fetch-depth;
- **state the minimum detectable effect** ("detect a 10% p99 regression at 95% confidence") and derive
  `rounds`/`warmups` from it. "Raise from 5/1" with no target is itself unfalsifiable;
- **state the pass condition.** The current artifact fails handshake-latency p95 **672.9 ms vs a 500 ms
  threshold**, and making the harness open-loop will make measured tail latency *worse*. Thresholds are
  recalibrated from the first open-loop capture; the release gate is "no non-overlapping-CI regression
  vs baseline", **not** the stale 500 ms absolute.

## Verification — two tiers (rev 1's single block was unaffordable and would have been skipped)

Ten commands including two full Rust builds, two clippy runs, two cargo-audits and two artifact builds
after each of ~35 phases will not happen. Skipping would then occur by drift rather than by decision —
the exact failure this audit is about.

**Per-phase fast gate:** `bun run typecheck` · the affected test suite · clippy on the touched crate.

**Full gate at every group boundary (A→B, B→C, C→D, D→E, final):**
```
rustup run 1.95.0 cargo fmt --all -- --check
rustup run 1.95.0 cargo clippy --all-targets --all-features -- -D warnings
rustup run 1.95.0 cargo test --workspace
cd crates/wasm && rustup run 1.95.0 cargo clippy --all-targets --all-features -- -D warnings
cd crates/wasm && rustup run 1.95.0 cargo test --all-features
bun run typecheck && bun run test
bun run build:native && bun run build:wasm
rustup run 1.95.0 cargo-audit audit -f Cargo.lock
rustup run 1.95.0 cargo-audit audit -f crates/wasm/Cargo.lock
```

**Landmines:** always `rustup run 1.95.0` (mise default 1.85.0 cannot build the workspace — rcgen/time
need ≥1.88; bare `cargo` gives a misleading exit 101 that is *not* a code failure) · wasm32 clippy needs
`CC_wasm32_unknown_unknown`/`AR_wasm32_unknown_unknown` → Homebrew LLVM clang · `crates/wasm` is **not**
a workspace member, always run it separately · baseline at `fe571ba`: **361 pass / 1 fail** (B4), all
Rust green, cargo audit clean on both lockfiles, reproducible-build verify passes.

## Working rules

≤5 files per phase · re-read before editing · **`replace_all` on near-identical blocks has burned this

were reverted?* · when two sources disagree on something security-critical, **read the source** rather

## Definition of done

Every claim in `docs/release-status.json` is `passed` and bound to the release commit with a real
artifact, and the promotion tool (D4) flips `readiness` **on evidence it verifies** — not because anyone
edited the manifest. Every gate green. Zero P0–P2. The false-green mechanisms replaced by ones that
would actually fail if the thing they cover broke — with B5 and B2 held to the hardening above, since
those are the two whose replacements could otherwise become better-looking unfalsifiable gates.
