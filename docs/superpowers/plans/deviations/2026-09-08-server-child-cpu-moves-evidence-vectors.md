# Deviation — `serverChildCpu` moved the pinned cohort evidence vectors

**Date:** 2026-09-08  
**Candidate:** the physical-budget amendment's slice 4 commit  
**Plan:** physical-budget amendment D6 ("the snapshot receipt has no hex
pin … the pinned hex vectors under `fixtures/cohort-evidence-vectors/` move
only through the slice 3 regeneration")

## Discovery

D6 predicted that adding `serverChildCpu` to `rig-server-snapshot-receipt/v1`
would not move the pinned `cohort-observation-evidence/v1` vectors, because
the Mac evidence does not embed the snapshot receipt. By execution it does
move them: the Mac cohort session admits the receipt by its closed key set
(`rig_record_facts` → `exact_fields`, `secure_fs.rs`), so the Rust test
harness's receipt fixture had to carry the new key, and the evidence's
`cohortAdmissionReceipt` member binds `rigServerSnapshotReceiptSha256` — the
digest of that receipt. With the key set at 28, both vectors kept their
sizes (507,198 and 133,171 bytes) and changed their digests:

- chat 1k: `a543d54d…` → `f5de5f28…`
- ticker 250: `e8e9a64a…` → `58cbcb79…`

Confirmed the other way: with the fixture's receipt left at 27 keys the Mac
session refuses it at admission (`mac_cohort_runtime.rs:1303`), so the
pre-amendment vectors cannot be kept.

## Resolution

Regenerated under the Rust owner via `WTB_EVIDENCE_VECTOR_DIR` from
`mac_cohort_runtime.rs` `evidence_vector`, the same mechanism slice 3 used;
the four hex files under `tools/compare/fixtures/cohort-evidence-vectors/`
are the regenerated bytes, and the digests are re-pinned in
`mac_cohort_runtime.rs` (`CHAT_1K_EVIDENCE_SHA256`,
`TICKER_250_EVIDENCE_SHA256`) and `cross-supervisor-protocol.test.ts`
(`EVIDENCE_VECTORS`). The `rig-measure-start-ack/v1` pin did not move, as D6
requires.
