  invoke `waitBidiCapacity` or `waitUniCapacity`.
- `bun run typecheck` rejected the incorrect direct
  `WasmWebTransport extends WebTransportLike` assertion. The public W3C facade
  intentionally satisfies the shared contract through `wasmToWebTransportLike`.
- Production `packages/webtransport/src/index.ts` used `Bun.sleep` in the
  client stream-credit fallback, contradicting the declared Node and Deno
  runtime support.

### Resolution

- Added abort-aware `sleep` and `withDeadline` helpers using only
  `globalThis.setTimeout` and `globalThis.clearTimeout`; timers and abort
  listeners are released on every settlement path.

  whenever exposed by the addon. Older addon shapes use the same bounded,
  exponentially backed-off portable waiter rather than an undefined callback.
- The outer deadline bounds both native notification waits and polling fallback
  waits, uses `performance.now()` rather than wall-clock time, and preserves
  `E_BACKPRESSURE_TIMEOUT` diagnostics across NTP and clock adjustments.
- The compile-time proof now checks the WASM adapter return type without casts
  or weakening `WebTransportLike`.
- A source-policy regression test scans production TypeScript and rejects any
  future `Bun.sleep` dependency.

## Task 4: Native server datagram Promise backpressure

### RED evidence

- With one inbound datagram consuming the configured session/global byte
  budget, a second server `sendDatagram()` settled immediately instead of
  remaining pending until capacity returned.
- Under the same pressure with a 100 ms deadline, the send rejected immediately
  with `E_QUEUE_FULL` rather than `E_BACKPRESSURE_TIMEOUT`.

### Resolution

- Added dedicated per-session and server-owned datagram-capacity notifications
  rather than reusing stream-count credit or a process-wide wake primitive.
- A datagram reservation wait registers both notification futures before its
  final reserve re-check, uses Tokio's monotonic `Instant`, and observes a
  sticky lifecycle flag from the same registry snapshot. Close wins over
  timeout, including close-before-registration and close-during-reserve races.
- Direct outbound release and `DatagramReservation::Drop` both release global
  and session byte reservations exactly once, then wake the affected session
  and only the owning server's waiters. The ingress path creates the RAII guard
  immediately after accounting succeeds, before payload or channel-slot work.
- The first auto-review round found and closed four valid issues: a missing
  direct-send wake, process-wide cross-server wakeups, absent close-while-blocked
  proof, and a post-reserve teardown leak window.
- Focused Rust coverage proves direct-release progress, pre-notify and
  pre-close race safety, chained progress for multiple waiters, cross-session
  owner wakeup, unrelated-owner isolation, and balanced teardown counters.
