### Resolution

- Native graph: `quinn 0.11.11`, `quinn-proto 0.11.16`, `rustls 0.23.42`,
  `rustls-webpki 0.103.13`, `aws-lc-rs 1.16.3`, and `aws-lc-sys 0.40.0`.
- WASM graph: `quinn-proto 0.11.16`.
- Both lockfiles use patched `time 0.3.47`, closing `RUSTSEC-2026-0009`
  instead of relying on the former repository-wide audit exception.
- Both graphs use `rcgen 0.14.8`. The patched `time 0.3.47` and current rcgen
  line require Rust 1.88 or newer; verification therefore uses the repository's
  documented stable-Rust baseline (stable 1.95 on this host), not the host's
  unrelated mise-global Rust 1.85 override.
- Server PEM parsing now uses `rustls::pki_types::pem::PemObject`, already
  shipped through `rustls`, so `rustls-pemfile` is absent from the graph.
- The rustls update exposed that the pinned-hash verifier incorrectly built a
  WebPKI chain verifier solely to delegate handshake-signature checks; empty
  platform roots could then reject valid pin-only configuration. The pin path
  now verifies TLS signatures directly with the explicit ring provider while
  retaining its hash, validity-window, and ECDSA P-256 checks.
- Test and release workflows install `cargo-audit 0.22.2` and audit both
  lockfiles without advisory ignores.
- The repository-wide `.cargo/audit.toml` exception for `RUSTSEC-2026-0009`
  was deleted, so local and CI audits share the same zero-ignore policy.
